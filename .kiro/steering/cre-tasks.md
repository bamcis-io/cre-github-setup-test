# Every task in this project, and its switches

Generated by `npx projen` from the project's tasks: it lists exactly what `npx projen <task>` runs
here. When to use which, what to ask first and the exit codes: `cre-tooling.md`. Each task that
takes arguments also prints its usage with `--help`.

## Tasks that take arguments

### `branch`

`npx projen branch <type>/<description>`

Start new work: create <name> from origin's default branch (just fetched), carrying uncommitted changes.

- `--branch`: the new branch name (instead of the positional one)

Creates the branch from origin's default branch, just fetched (from a detached HEAD: at HEAD), and carries uncommitted changes onto it. On the default branch, unpushed commits move onto the new branch and the local default branch is reset to origin's. Exit 10 refused (a bad name, a name already used, an unknown base), 30 on a conflict, nothing changed; 20 interrupted or an internal error, the repo put back. Through `npx projen` the exit is 1: the code is on the `RESULT` line.

### `cfs:curl`

`npx projen cfs:curl [--json] [-i] <GET|POST|PUT|PATCH|DELETE|HEAD> <url-or-/path> [body]`

Call a CloudFront Signer (Midway) protected URL: cfs:curl [--json] [-i] GET https://dxxxx.cloudfront.net/path [body]

- `--json`: send the body as application/json (default: a form)
- `--include`: print the response headers first (also -i)

A `/path` needs CFS_URL. GET, HEAD and DELETE take no body. Exit 0 2xx/3xx | 1 4xx/5xx | 2 bad arguments | 11 no Midway cookie, or the CloudFront Signer handshake failed (a CloudFront 403 page is 1, naming both causes) | 20 the request failed. Through npx projen only 0 or 1 reaches the caller and there is no RESULT line (stdout is the response body): the stderr message says which. A POST changes the demo's state: only when the user asks.

### `cfs:onboard`

`npx projen cfs:onboard [--domain <dxxxx.cloudfront.net>] [--profile <p>] [--status | --offboard]`

Onboard the edge distribution at CloudFrontSigner (Midway; after the first edge deploy, and again after the edge is renamed or recreated). --status | --offboard

- `--domain`: the distribution (default: the edge stack's EdgeDomainName)
- `--profile`: the profile to read the edge stack with
- `--status`: only say whether it is onboarded (ONBOARDED=true|false)
- `--offboard`: undo it (the edge then answers 403)

After the first edge deploy, and again after the edge stack is renamed or recreated (a new distribution and domain). Exit 0 done | 10 bad input or no edge domain | 11 Midway expired | 20 the portal failed. Ask the user first.

### `ci:rerun`

`npx projen ci:rerun [--sha <sha>] [--all]`

Retry the failed jobs of the deploy of main's head; --all runs the whole deploy again. Then: npx projen watch --sha <sha>.

- `--sha`: main's head, given explicitly; any other commit is refused (exit 10): re-running an older deploy would put its templates back
- `--all`: run the whole deploy again (a redeploy without a commit), not only the failed jobs

Then `npx projen watch --sha <sha>`. Exit 0 started | 10 nothing to re-run | 11 credentials | 20 the provider refused, or the deploy couldn't be read (re-run). Ask the user first.

### `commit`

`npx projen commit --message "<type>(<scope>): <description>" [--files "<paths>"] [--branch <new>] [--allow-secret-path <path>]...`

Validate (synth + build), stage and commit. Never pushes. Needs --message.

- `--message`: the commit message (Conventional Commits; also -m). Required
- `--files`: stage only these paths (space- or newline-separated; repeatable). Globs as a shell reads them: `src/*.ts` stays in src/, `src/**/*.ts` goes below. Default: every change
- `--branch`: move to this new branch first when the current one can't take the commit (also -b)
- `--allow-secret-path`: stage a file whose path looks like a credential (e.g. a test fixture named `*.pem`); repeatable

Validates (synth + build), stages, commits. Never pushes.

### `deploy`

`npx projen deploy [--stack <id>]... [--no-build] [--profile <p>]`

Run the deploy pipeline locally (builds first): deploy:upload, deploy:stack per stack in order, deploy:prune. [--stack id] [--no-build] [--profile p]

- `--stack`: deploy only this stack (repeatable); the outputs of the stacks it needs are read from AWS
- `--no-build`: skip the build that runs first
- `--profile`: the AWS profile (default: the ambient credentials)

The pipeline on your machine; `deploy:prune` runs only for a full deploy (not with `--stack`). Variables come from the environment, `.cre/deploy.env`, then a prompt. Exit 0 deployed | 1 failed or bad arguments (no RESULT line). Ask the user first.

### `git:status`

`npx projen git:status`

Classify the repo state and say what `push` would do. Changes nothing (it only fetches).

Changes nothing in the repo or on the remote (it fetches, and holds the cre-git lock while it reads): classifies the repo and says what `push` would do, including each refusal push would make before changing anything (`Push would: refuse (<STATE>)`, the same check push runs).

### `push`

`npx projen push --message "<type>(<scope>): <description>" [--title "<MR/PR title>"] [--branch <new>] [--files "<paths>"] [--allow-secret-path <path>]...`

Validate, commit, push, open/update the MR/PR and arm auto-merge. Needs --message; --branch when a new branch is needed.

- `--message`: the commit message (also -m). Required
- `--title`: the MR/PR title (also -t). Default: the message's first line
- `--branch`: the new branch, when the current one can't take the change (also -b)
- `--files`: commit only these paths (repeatable; `*` stays in one directory, `**` crosses them). Default: every change
- `--allow-secret-path`: allow a credential-looking path; repeatable

Validate, commit, push, open or update the MR/PR, arm auto-merge. Every commit it would send is checked first: a credential (`SECRET_IN_HISTORY`) or a file over `CRE_MAX_FILE_MB` (`LARGE_FILE_IN_HISTORY`) committed with plain git is refused. Exit 0 done | 10 refused | 20 validation failed | 30 conflict | 40 incomplete (re-run resumes). Another task running in the clone is `LOCKED` (10): wait for it, never remove the lock. Ask the user first.

### `setup:github-app`

`npx projen setup:github-app [--alias <a>] [--key-dir <dir>] [--wait <s>]`

Create (once) or check your CRE automation GitHub App, aws-cre-automation-<alias>, and its key in ~/.cre.

- `--alias`: your Amazon alias (default `whoami`); the App is aws-cre-automation-<alias>
- `--key-dir`: where its key lives (default ~/.cre)
- `--wait`: seconds to wait for the "Create GitHub App" click (default 600; 0 opens nothing and doesn't wait)

One App per builder, for all their repos: it exists and is yours, its key is one of its keys, and it has Contents, Pull requests and Workflows write; otherwise GitHub's manifest flow makes it (one browser click). Exit 0 ready | 10 refused (another owner's App by that name, no or wrong key, missing permissions, or not created yet: the page's address is printed) | 11 gh isn't signed in | 20 a call failed.

### `setup:github-public`

`npx projen setup:github-public --profile <p> [--dns-profile <p>] [--allow-production <account>]... [--dry-run]`

A private repo made public, end to end (from a clean main): scan the history for credentials (--dry-run stops there), make it public with the AWS environment, move the deploy trust and role secrets to that environment, then set github.visibility in .projenrc.ts and merge the regenerated workflows as a PR.

- `--profile`: the deploy account's AWS profile (the runner role's trust moves to the `AWS` environment)
- `--dns-profile`: the hosted zone account's profile, when the project has one: its stack's trust moves too
- `--allow-production`: an account Isengard calls production, or can't classify, as for setup:aws. Only after the user agrees
- `--dry-run`: scan the history and say what becomes readable; change nothing
- `--dir`: the project's clone (default: here)
- `--repo`: set by the task (`<owner>/<repo>` from `repository`); a second value is refused
- `--project`: set by the task (.projenrc.ts `name`); a second value is refused
- `--app-slug`: set by the task (`github.appSlug`): the App approves and merges the switch's PR; a second value is refused
- `--partition`: set by the task (.projenrc.ts `partition`, default aws); a second value is refused

From main with nothing uncommitted. Makes the repo public: running it is the decision, so it doesn't ask. Only when the user asks (show them `--dry-run` first). Refused (10) when the history holds something shaped like a credential. The trust takes main's subject as well as the environment's until the switch has merged and main's earlier deploys have finished, so main keeps deploying throughout. Repo-level variables and secrets it didn't set are named: one the workflows read is moved with setup:repo (give the value again), one nothing reads is a leftover to delete. Re-running carries on where it stopped (.git/cre-github-public.json). Exit 0 | 10 refused | 11 credentials | 20 a call failed.

### `teardown`

`npx projen teardown [--orphans] [--stack <id>...] [--profile <p>] [--dry-run] [--allow-production[=<account>]]`

Delete the stacks in reverse deploy order. Running it deletes; --dry-run only lists them, so run that first. [--orphans] [--stack id] [--profile p]

- `--orphans`: only the orphans (from main's committed plan, freshly fetched; refused while main's plan can't be read, this branch's plan differs, or main's stacks aren't all deployed: merge and deploy first), newest first
- `--stack`: only this stack (repeatable); refused while a deployed stack still takes its outputs. With --orphans: only this orphan
- `--profile`: the AWS profile
- `--dry-run`: print what it would delete, in order, and delete nothing; where a real run would refuse, the list, then why (exit 10)
- `--allow-production`: delete in a production account (Isengard IsProduction, or one it can't classify); `=<account>` for only that one. Refused (10) without it; a dry run needs none. Only after the user agrees

Reverse deploy order. Buckets, setup roles and retained resources stay; a stack in another account is skipped. Running it deletes (it doesn't ask): show the user `--dry-run` first, and run it only once they agree.

### `update-template`

`npx projen update-template [--from <path>] [--allow-branch]`

Pull the cre-demo-template clone, refresh projenrc/cre, cre-constructs and the skill links from it, then synth + build.

- `--from`: the template clone (recorded for next time). Without it: $CRE_TEMPLATE_DIR, the clone `.cre/template.json` records (older projects: projenrc/cre/SOURCE.json), then the sibling directory
- `--allow-branch`: use a clone that is on another branch, as it is (testing a template change)

Exit 0 updated or current | 10 refused, nothing changed | 20 synth/build failed after copying (the restore command is printed). Its last stdout line is `RESULT code=<n> step=update-template`. Ask the user first.

### `watch`

`npx projen watch [<n> | --branch <b> | --sha <sha>] [--until checks|merged|deployed] [--timeout <s>] [--interval <s>] [--start-timeout <s>]`

Read-only: follow an MR/PR from its checks through the merge to the deploy of its merge commit. [<n>|--branch b|--sha s] [--until checks|merged|deployed]

- `--branch`: follow the latest MR/PR from this branch (e.g. the weekly upgrade branch)
- `--sha`: follow only the deploy of this commit on main
- `--until`: stop after this stage: checks, merged or deployed (default)
- `--timeout`: give up after this many seconds (default 3600)
- `--interval`: seconds between polls (default 15)
- `--start-timeout`: how long to wait for a pipeline/run to appear (default 300)

Read-only. `<n>` is MR !n / PR #n; none of them: the current branch's MR/PR. Exit 0 reached --until | 10 nothing to watch | 11 credentials | 20 closed unmerged | 30 a job failed | 40 timed out, never started, or the MR/PR couldn't be read (re-run).

**Setup** (`setup:aws`, `setup:repo`): account, DNS and repository setup, used once or twice in a project's life. They change the AWS account or the repo, so ask the user first. Their usage and switches are in `cre-pipelines-detail.md` ("Setup tasks and their switches").

## Other tasks

|---|---|
| `build` | Full release build |
| `check:generated` | CI only: fail when the committed generated files (pipeline, cre-stacks.json, ...) are not what npx projen makes |

| `compile` | Only compile |

| `install` | Install project dependencies and update lockfile (non-frozen). Changes the lockfile; CI runs `yarn install --immutable` instead. |
| `install:ci` | Install project dependencies using frozen lockfile |
| `package` | Stage CFN assets and zip into dist/content.zip |
| `skills:doctor` | Check that the vended agent skills (.kiro/skills/* symlinks into cre-demo-template) resolve. |
| `synth` | Synthesizes your cdk app into cdk.out |
| `test` | Run tests |
| `test:update` | Update jest snapshots |
| `test:watch` | Run jest in watch mode. Interactive (watch mode): not for an agent session. |
| `upgrade` | upgrade dependencies. Only when the user asks: CI opens a weekly upgrade MR/PR (and skips while a person's commit is on its branch). |

**Steps of `build` / `deploy` / CI, run by them in order, never on their own:** `bundle`, `deploy:prune`, `deploy:s3`, `deploy:stack`, `deploy:upload`, `package:assets`, `package:content`, `post-compile`, `post-upgrade`, `pre-compile`, `synth:silent`.

**Never run** (they bypass the pipeline or projen itself): `eject`.
